# SmolVLA 云台扫描第一批数据录制与训练计划

本文档用于规划第一批 `smolvla_scan_v2` 数据录制、后续训练、实机验证和补数据闭环。目标不是让模型直接替代 50Hz 的底层云台控制，而是让模型学习“人如何扫描、发现目标、找回目标、粗略跟随目标”的操作意图。

推荐架构：

- SmolVLA/策略模型：输出粗粒度云台意图，例如往哪个方向扫、是否继续找回、是否需要 zoom。
- 经典控制链路：继续保留检测、OSTrack、DKF、servo、限速和急停，用于实时居中、安全约束和控制兜底。
- 人工操作数据：用于学习人的扫描策略和异常处理方式，而不是单纯学习 PID 控制。

## 1. 训练目标

第一版模型希望学到以下能力：

- 像人工一样进行左右、上下扫描；
- 发现人/车目标后，将目标粗略带到图像中心附近；
- 目标丢失后，围绕上一次目标位置或运动方向进行局部找回；
- 目标静止且已经居中时，不要来回摆动；
- 对没有人/车的场景不要乱锁、乱动；
- 对小目标、远距离目标有基本扫描意识。

当前动作定义：

```text
action_vector = [yaw / 100, pitch / 100, zoom_direction]
```

其中：

- `yaw`：水平转动，范围约为 `[-100, 100]`；
- `pitch`：俯仰转动，范围约为 `[-100, 100]`；
- `zoom_direction`：`-1` 缩小，`0` 不变，`1` 放大。

## 2. 第一批录制目标

第一批建议录制 `80` 段 episode，每段 `20-40s`。每段只做一个明确任务，不要一段里混合多个场景。短而干净的数据，比一段很长但混乱的数据更适合训练。

| 组别 | 数量 | 目标 | 录制内容 |
| --- | ---: | --- | --- |
| A | 12 | 人 | 从没有锁定目标开始，人工扫描，发现人后居中 |
| B | 12 | 车 | 从没有锁定目标开始，人工扫描，发现车后居中 |
| C | 10 | 人 | 人已经出现后，人工稳定跟随并保持居中 |
| D | 10 | 车 | 车已经出现后，人工稳定跟随并保持居中 |
| E | 10 | 人 | 人目标丢失、遮挡或出画面后，人工找回 |
| F | 10 | 车 | 车目标丢失、遮挡或出画面后，人工找回 |
| G | 8 | 静止目标 | 目标已经居中，人工保持不动或做极小修正 |
| H | 8 | 负样本 | 没有人/车目标时，人工扫描或停止，不要乱锁 |

第一批最低质量要求：

- 最终至少筛出 `50` 段有效 episode；
- 扫描/找回类 episode 的非零动作帧比例建议超过 `30%`；
- 要包含左扫、右扫、上扫、下扫；
- 要包含近距离、中距离、远距离目标；
- 要包含人和车；
- 要有静态目标不动的数据，否则模型容易学成一直微调；
- 要有无人/无车负样本，否则模型容易在背景上乱找目标。

## 3. 录制流程

打开面板：

```bash
http://127.0.0.1:7860
```

每段录制流程：

1. 准备好一个明确场景，例如“远距离人，从左侧扫描发现”。
2. 点击 `REC START`。
3. 人工自然操作云台，不要刻意一帧一帧修正。
4. 完成任务后立刻点击 `REC STOP`。
5. 在纸面或单独文本里记录该段含义：

```text
episode时间，组别，目标，人/车，距离，成功/失败，备注
```

注意：

- 不要录太长的开头等待和结尾空闲。
- 不要在同一段 episode 里先扫人、再扫车、再停很久。
- 如果画面卡死、倒置、RTSP 延迟异常，这段要标记为失败或删除。
- 如果人工操作明显误操作，这段不要放进第一批训练集。

## 4. 好数据和坏数据

好的扫描数据：

- 开始时目标不在中心或没有目标；
- 操作者有明确扫描方向；
- 目标出现后，操作者减速并把目标带到中心；
- 最后 `2-5s` 保持稳定。

好的找回数据：

- 目标刚刚丢失或快要丢失；
- 操作者围绕上一次目标方向局部搜索；
- 找回目标后重新居中；
- 不做无意义的大范围乱扫。

好的静止数据：

- 目标已经在中心附近；
- 大部分动作是 `0`；
- 只有少量小修正；
- 没有反复左右摆动。

坏数据：

- 任务是扫描/找回，但大部分时间动作是 `0`；
- 人工操作和目标位置关系不一致；
- 目标不可见时长时间随机操作；
- 自动控制和人工操作互相打架；
- 画面倒置、卡死、严重掉帧；
- 一段 episode 混入多个完全不同任务。

## 5. 录完后的质量检查

查看最近 episode：

```bash
find recordings/smolvla_scan -maxdepth 1 -type d -name 'episode_*' | sort | tail
```

运行统计脚本：

```bash
python scripts/analyze_smolvla_recordings.py recordings/smolvla_scan
```

重点看：

- `schema` 是否为 `smolvla_scan_v2`；
- `frames` 是否和录制时长匹配，25fps 下 20s 大约是 500 帧；
- `nz%`，也就是非零动作比例；
- `top_state` 是否符合该段任务；
- `classes` 是否能看到人/车类别；
- `video.mp4` 是否真实展示了预期场景。

建议第一批筛选标准：

- 扫描/找回 episode：`nz% >= 30%`；
- 静止 episode：`nz%` 可以低，但画面必须目标居中；
- 负样本 episode：允许动作存在，但不能出现乱锁目标；
- 严重卡顿、倒置、误操作 episode 直接剔除。

## 6. 后续训练路线

### 6.1 数据转换

将 `smolvla_scan_v2` 转成 LeRobot 数据格式：

- 图像输入：使用 `video.mp4` 或 `frames/*.jpg`；
- 状态输入：使用 `observation.state_vector`；
- 动作标签：使用 `action_vector`；
- 可选语言指令：

```text
扫描并居中人或车目标
```

注意：训练集和验证集要按 episode 切分，不能按帧随机切分。否则同一段视频的相邻帧会同时出现在训练和验证里，验证结果会虚高。

### 6.2 先训练小模型 baseline

先训练一个简单行为克隆模型，例如：

- 图像编码器：ResNet/ViT；
- 状态输入：`state_vector`；
- 输出头：MLP 输出 `[yaw, pitch, zoom_direction]`。

这个 baseline 的作用是验证数据是否能学。如果 baseline 完全学不动，直接上 SmolVLA 也大概率只是更慢地失败。

### 6.3 再微调 SmolVLA

第一版 SmolVLA 建议：

- 初始模型：`lerobot/smolvla_base`；
- 训练步数：先跑 `10k-20k steps`；
- 验证集：按 episode 留出 `10-20%`；
- 每隔几千步保存 checkpoint；
- 不要只看训练 loss，要看离线回放和实机指标。

官方 SmolVLA/LeRobot 资料：

```text
https://github.com/huggingface/lerobot/blob/main/docs/source/smolvla.mdx
```

## 7. 评估指标

离线回放指标：

- yaw/pitch 动作 MAE；
- yaw/pitch 方向预测准确率；
- 目标居中时是否输出接近 0；
- 静止目标是否出现振荡动作；
- 丢失找回时，扫描方向是否接近人工操作；
- zoom 是否被过度使用。

实机指标：

- 从开始扫描到目标进入中心附近的时间；
- 找到目标后的平均中心误差；
- 目标丢失后的找回时间；
- 静止目标时的左右/上下摆动次数；
- 是否出现过大速度指令；
- 是否出现长时间错误方向扫描。

## 8. 潜在问题与规避办法

### 8.1 数据量不足

问题：第一批数据太少，模型只记住少数场景，换个角度或背景就不会操作。

规避：

- 第一批至少保留 `50` 段有效 episode；
- 后续每轮补 `20-40` 段针对性数据；
- 人、车、近、中、远、静止、运动、负样本都要覆盖。

### 8.2 停止帧太多，模型学成不动

问题：如果大部分帧都是 `yaw=0, pitch=0`，模型会倾向于输出 0，扫描能力学不出来。

规避：

- 扫描/找回类 episode 的 `nz%` 尽量超过 `30%`；
- 静止不动数据要单独作为 G 组，不要混进扫描组；
- 训练时可以对扫描/找回样本加权，避免被静止样本淹没。

### 8.3 人工操作不一致

问题：同样画面下，有时向左，有时向右，模型会学到模糊动作，输出变慢或发抖。

规避：

- 每段任务要明确；
- 操作者尽量形成固定习惯，例如目标在左侧就先左扫；
- 明显误操作 episode 不进训练集；
- 训练前做人工筛选。

### 8.4 人工动作与图像存在延迟

问题：云台、RTSP、面板输入都有延迟，当前帧对应的动作可能是人根据前一小段画面做出的反应。直接监督当前帧动作，可能造成模型学到滞后控制。

规避：

- 数据里已经记录 `human_action.age_ms`、`frame_age_ms`、`dt`；
- 转数据集时可以尝试动作时间对齐，例如把动作标签相对图像前后平移若干帧；
- 对比不同动作延迟补偿下的离线误差；
- 实机部署时仍保留 DKF/servo 做预测和限幅。

### 8.5 自动控制和人工控制混在一起

问题：如果录制时自动跟踪也在动，人又在手动修正，模型可能不知道哪个动作才是专家动作。

规避：

- 第一批主要录“人工示教”，减少自动控制干扰；
- 数据里保留 `action` 和 `autonomy_action`，训练时优先学习人工 `action_vector`；
- 如果要学习人接管自动系统，要单独建一组“人类纠偏”数据，不要和纯人工扫描混为一谈。

### 8.6 检测器漏检导致策略数据混乱

问题：小目标人/车检测不到时，状态里没有检测框，但人依然能凭视觉操作。模型可能学会依赖不稳定检测结果。

规避：

- 训练输入必须保留原始图像，不要只依赖 detection；
- 远距离人/车要单独多录；
- 后续需要同时训练更强的人/车检测模型；
- 对检测失败但人工成功找回的 episode 要保留，这是学习扫描策略的关键数据。

### 8.7 跟踪框漂移污染状态

问题：OSTrack 跟跑偏或框突然变大时，`tracker_bbox` 会误导模型。

规避：

- 数据里同时保存图像、检测框、tracker bbox、control bbox；
- 训练时可以把 bbox 状态作为辅助输入，而不是唯一输入；
- 明显跟踪框错误的 episode 要标记；
- 后续可以增加“tracker_valid”或质量评分字段。

### 8.8 静止目标摆动被模型学进去

问题：如果静止目标场景里，人或自动控制一直左右微调，模型会学到目标居中时也要动。

规避：

- G 组静止数据要专门录“目标居中且不动”；
- 对静止目标反复摆动的 episode 不要放入训练；
- 训练评估必须包含“目标居中时动作接近 0”的指标。

### 8.9 zoom 数据不足

问题：如果 zoom 操作很少，模型学不会什么时候放大/缩小；如果乱用 zoom，又会学到过度变焦。

规避：

- 第一批可以先弱化 zoom，只让模型主要学 yaw/pitch；
- 后续单独录 zoom 场景：远距离小目标需要放大，目标丢失或视野过窄需要缩小；
- 训练时可以先不启用 zoom 输出，等 yaw/pitch 稳定后再加入。

### 8.10 类别不平衡

问题：如果人数据远多于车，模型可能更偏向人的扫描尺度和速度；反过来也一样。

规避：

- 第一批人/车数量尽量接近；
- 统计脚本查看 `classes`；
- 训练采样时按目标类型均衡。

### 8.11 场景分布过窄

问题：只在一个高度、一个角度、一个背景录制，模型在新环境泛化差。

规避：

- 改变俯仰角、距离、背景、光照；
- 录制不同方向进入画面的目标；
- 加入负样本和干扰目标。

### 8.12 模型输出频率和控制频率不一致

问题：SmolVLA 通常按视频帧率输出，底层云台控制是 50Hz。如果直接把模型输出当 50Hz 控制，可能卡顿或过冲。

规避：

- 模型输出作为视频帧率级别的目标速度或策略意图；
- 底层 `speed_ramp` 和 servo 继续以 50Hz 平滑执行；
- 对模型输出做限速、死区和急停保护。

### 8.13 实机直接闭环有安全风险

问题：模型第一版可能输出错误方向、过大速度或持续动作，导致云台乱转。

规避：

- 第一版必须 guarded mode；
- 限制最大 yaw/pitch；
- 超过中心误差、目标丢失、画面卡顿时由经典逻辑接管；
- 人工面板保留 stop 和 manual override。

### 8.14 离线 loss 好但实机不好

问题：行为克隆的 loss 低，不代表实机闭环稳定。模型一旦产生小偏差，后续画面分布会偏离训练数据。

规避：

- 做实机 guarded 评估；
- 记录模型动作和人工纠偏；
- 对失败场景补数据；
- 不要只用 loss 作为上线标准。

## 9. 补数据闭环

第一版模型训练后，按如下方式补数据：

| 失败现象 | 应补数据 |
| --- | --- |
| 小人目标找不到 | 远距离人、弱纹理背景、人很小的扫描数据 |
| 车能跟，人不行 | 增加人目标扫描和跟随 |
| 人能跟，车不行 | 增加车目标扫描和跟随 |
| 目标居中还乱动 | 增加静止目标零动作数据 |
| 丢失后找不回 | 增加从丢失到找回的局部搜索数据 |
| 扫描方向错误 | 增加明确方向的扫描数据，例如目标在左就左扫 |
| 输出太慢 | 增加人工快速起步、接近中心后减速的数据 |
| 输出过猛 | 增加平滑、小步、减速的数据 |
| 背景误触发 | 增加负样本和干扰目标数据 |
| zoom 乱用 | 增加“不需要 zoom”的反例和“确实需要 zoom”的正例 |

每一轮补数据建议：

1. 从实机失败日志中挑出 3-5 类最常见问题。
2. 每类补 `5-10` 段 episode。
3. 总共补 `20-40` 段。
4. 保留上一版验证集，不要为了新数据把验证集也换掉。
5. 从上一版最好 checkpoint 继续训练。
6. 只有实机指标提升后，才替换部署模型。

## 10. 第一周执行计划

Day 1：

- 录 20 段：A/B/G/H；
- 跑统计脚本；
- 检查 v2 数据字段是否完整；
- 修正录制流程问题。

Day 2：

- 录 30 段：C/D/E/F；
- 人工看视频，删除明显坏数据；
- 统计人/车和非零动作比例。

Day 3：

- 针对不足场景再录 30 段；
- 冻结第一批训练集；
- 划分训练集和验证集。

Day 4：

- 转换为 LeRobot 数据格式；
- 训练小模型 baseline；
- 检查动作对齐问题。

Day 5：

- 微调第一版 SmolVLA；
- 做离线回放评估。

Day 6：

- guarded mode 实机测试；
- 记录失败案例和人工纠偏。

Day 7：

- 按失败类型补数据；
- 训练第二版；
- 对比第一版和第二版实机指标。
